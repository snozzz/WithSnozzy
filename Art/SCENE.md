# 做场景，以及让 Snozzy 和场景互动

## 先定视角

两台"摄像机"要分开想：**房间的透视**和**角色的朝向**。它们不必一致，
而且刻意不一致才划算。

- **房间／桌子：明显的 3/4 俯视。** L 形桌，一条边略斜地正对镜头（她坐在这边后面），
  另一条边向画面右后方延伸出去——电脑、书堆、台灯摆在这条侧翼上。
  视平线略高于她的眼睛，能看见桌面纵深。
- **角色：只转 15 度。** 理由在 `SNOZZY_LIVE2D.md` 里，一句话是转多了绑定工作量翻倍。

L 形桌是这套构图的关键：它让画面同时有"正对镜头的工作面"（她的手在这里活动，
看得清）和"向纵深延伸的陈列面"（摆一堆东西，制造信息密度），
而不需要把角色本身转过去。

## 场景的分层

```
  ①房间背景      墙、窗（品红填充）、书架、挂饰            静态
  ②桌子本体      L 形桌板、桌腿、椅背                     静态
  ─────────────  【Snozzy】────────────────────────
  ③桌上道具      电脑、书、纸、笔筒、杯子、台灯…          每个一层
  ─────────────  【她的手臂姿势组】───────────────────
  ④前排道具      最靠近镜头、压在手前面的小物               每个一层
  ⑤UI
```

**每个道具必须是独立一层**，这是能不能做交互的分水岭。合成一张图的话，
屏幕就不能单独亮、书就不能翻页、笔就不能被拿起来。

道具清单（照着"现代学生的桌子"来，越杂越真）：

> 笔记本电脑（屏幕内容留空，我们在运行时程序化画）、外接键盘、
> 摊开的书、竖着码的书堆、散落的草稿纸、笔筒和几支笔、马克杯、
> 台灯、手机、便利贴、小镜子和护手霜、耳机、绿植、纸巾盒、猫

## 怎么生成

和做人物一模一样的手法：**画一张全景，然后链式剥离**。
道具之间透视和光照必须一致，所以不能一个个单独画。

> 二次元 lofi 插画风格的房间内景，2400×1600。
> **3/4 斜俯视**，视线略高于坐着的人的眼睛。
> 画面主体是一张**浅木色 L 形书桌**：一条边略斜地正对镜头，
> 另一条边向画面右后方延伸。
>
> 桌上摆满东西：打开的笔记本电脑（**屏幕填纯品红 #FF00FF**）、外接键盘、
> 摊开的书、竖着码的书堆、散落的草稿纸、笔筒和几支笔、马克杯、
> 金属台灯、手机、几张便利贴、小镜子和护手霜、耳机、一小盆绿植、纸巾盒。
> 东西要多、要随意，像真的有人在这儿生活。
>
> 左后方一扇窗，**窗玻璃部分填纯品红 #FF00FF**。右后方是书架。
> 现代、温暖、整洁但不刻意的学生房间。
>
> **不要画人。** 桌后留出坐人的空位。
> 均匀柔和的光，不要强投影。不要文字、水印、边框。

两处品红是给引擎留的洞：窗户后面塞程序化的天空（昼夜和天气全靠它），
电脑屏幕后面塞程序化的界面内容。

道具通常边缘清楚、和桌面色差大，比抠人物容易得多。

### 手动补的两件事

1. **每层的深度**：在 `scene.json` 里标 `behind`（在她身后）还是 `front`（在她身前）。
   电脑、书堆、台灯是 behind；杯子、前排小物是 front。
2. **可交互道具的锚点**：她要"看向电脑"，得知道电脑在画面的哪个位置。
   在清单里给这些道具补一个归一化坐标 `focus: [x, y]`。

## 交互怎么做

核心是引入一个 **Activity（活动）**——"她此刻在干什么"的单一真相来源。
它同时驱动三样东西，三样东西各自都很便宜，凑在一起才像"活的"。

```
                    ┌──→ 角色：ParamPose 切手臂 + 视线看向道具 + 低头幅度
   Activity ────────┼──→ 道具：屏幕亮度/内容、书翻页、笔在不在手上、热气
                    └──→ 声音：打字声、翻页声、杯子放下
```

```swift
enum Activity {
    case typing      // 敲键盘   → ParamPose 1，视线看屏幕，屏幕亮
    case reading     // 看书     → ParamPose 2，视线向下，书是摊开的
    case writing     // 写字     → ParamPose 3，视线看纸，笔在手上
    case sipping     // 喝东西   → ParamPose 4，杯子从桌上消失、热气变化
    case resting     // 发呆听歌 → ParamPose 0，视线飘，偶尔看向窗外
    case stretching  // 伸懒腰   → ParamPose 0 + 大幅呼吸
}
```

**Activity 由已有的 `FocusTimer.phase` 驱动**，不用另起一套：
`work` 阶段在 typing / writing / reading 之间随机漫游（每 40–90 秒换一次），
`shortBreak` / `longBreak` 走 sipping / stretching / resting，
`idle` 就是 resting。这样番茄钟不只是个计时器，而是真的改变了她在做的事。

### 优先级：先做便宜的

按"每分工作量换来的可信度"排序，别一上来就啃手臂：

1. **屏幕发光 + 内容变化**——一个发光矩形加程序化画的文档/代码行，
   一眼就有"她在用电脑"的感觉。工作量最小，收益最大。
   屏幕那块品红洞就是为这个留的。
2. **视线跟着当前活动走**——`Pose.lookX/lookY` 已经有了，
   只要把它指向 Activity 对应道具的 `focus` 锚点即可。几乎零成本。
3. **道具的小动画**——热气（`SteamOverlay` 已有）、台灯呼吸、
   手机偶尔亮一下、猫换姿势。都是 2D 变换和透明度。
4. **音效**——`Ambience` 那套基础设施已经在了，加打字声和翻页声即可。
5. **才是手臂姿势切换**。前四条做完，这一条是锦上添花而不是雪中送炭。

### 翻页、打字这类"动作"

不要做逐帧动画，成本和收益完全不成比例。用最省的做法：

- **打字**：手部姿势 1 出两张图（手指抬起/按下），按 6–8 Hz 交替，
  再叠一点点整体上下位移。看起来就是在打字。
- **翻页**：书出两三张不同页面的图，每隔一阵交叉淡入换一张。
  不做翻页的中间过程，人眼根本注意不到。
- **拿起杯子**：桌上的杯子层隐藏 + 手部姿势 4 显示，两件事同时发生。
  中间不用过渡——她的手抬起来的那一瞬间挡住了桌面，视觉上盖住了跳变。

## 引擎侧要改什么

现在 `SceneAssets` 里 room / desk / cats 是写死的字段，
换成"一组由 `scene.json` 描述的具名图层"，每层带 `depth`、`at`、`focus`。
这样以后加道具只改 JSON，不动 Swift——和现在改构图不用重新编译是同一个道理。

`Activity` 放在 `Features/` 里，和 `FocusTimer` 平级，
由它订阅 phase 变化并驱动 `Pose` 和场景层。

这两件事等素材到位再动手，现在写就是对着空气写。
